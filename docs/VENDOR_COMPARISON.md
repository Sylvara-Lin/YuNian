# 予念 vs 商业加固厂商 — 全模块深度对比

> 对比版本：予念六维安全 (2026-06) vs 360加固保 vs 梆梆安全 vs 几维安全
> 评估标准：✅ 完整实现 ⚠️ 部分实现/有降级 ❌ 未实现 🔸 依赖外部(付费)

---

## 一、DEX 保护

| 能力 | 360加固保 | 梆梆安全 | 几维安全 | 予念 |
|---|---|---|---|---|
| DEX 整体加密 | ✅ SM4-ECB | ✅ 多算法 | ✅ AES | ✅ SM4-ECB |
| DEX 函数抽取 | ✅ 函数级按需解密 | ✅ 细粒度抽取 | ✅ KiwiVM抽取 | ⚠️ Code Item提取(NOP填充) |
| DEX VMP 保护 | ✅ 自定义VM | ✅ VMP引擎 | ✅ **KiwiVM(核心产品)** | ✅ **28指令VMP+9预编译程序** |
| DEX2C 转译 | ✅ DEX→C | ✅ Java2C | ✅ **DEX2C(第4代壳)** | ✅ DEX→C(JNI) |
| 壳 DEX 最小化 | ✅ ≤12KB | ✅ ≤20KB | ✅ ≤15KB | ✅ **≤50KB(3类)** |
| 多 DEX 分片 | ✅ | ✅ | ✅ | ✅ 4分片独立加密 |
| 类按需加载 | ✅ DynamicClassLoader | ✅ | ✅ | ✅ DynamicClassLoader |
| ClassLoader 注入 | ✅ | ✅ | ✅ | ✅ LoadedApk反射 |

**DEX 小结**：予念在 DEX 保护上达到商业水平。DEX2C+VMP 双层与几维安全架构一致。函数抽取的"按需解密"机制略弱于360（360在方法入口hook，予念在ClassLoader层拦截），但整体深度相当。

## 予念独有优势

1. **零信任架构(PDP/PEP)** — 360/梆梆/几维均为传统加固模型，无持续评估
2. **差分隐私(ε-Laplace)** — 三厂商均无客户端隐私计算
3. **公开白皮书+渗透清单** — 三厂商均为黑盒商业产品
4. **完全开源** — 代码可审计、可定制、可独立演进
