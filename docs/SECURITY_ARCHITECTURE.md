# YuNian — 零信任安全架构设计方案

> 分支：`security/vmp-encryption`
> 目标：为 YuNian Android 应用构建企业级端侧安全防护体系

## 一、项目结构分析与模块重要性排序

### 1.1 模块拓扑

```
:app (入口) ← 启动流程、导航路由
├── feature:chat (聊天界面) ← AI对话核心交互
├── feature:companion (伴侣管理) ← 伴侣创建/编辑
├── feature:groupchat (群聊) ← 多AI群聊
├── feature:memory (记忆系统) ← 对话记忆管理
├── feature:settings (设置) ← 应用设置
├── feature:profile (个人页) ← 用户资料
├── feature:notification (通知/保活) ← 前台服务
├── feature:wechat (微信风格) ← UI风格
│
├── core:agent (Cordis Agent) ← Rust 设备端推理运行时（原 feature:localmodel 已退役）
├── core:common (基础工具) ← ContentFilter, 通用工具
├── core:database (数据层) ← Room, 6个Entity
├── core:network (网络层) ← AI API多后端
├── core:security (安全模块) ← JNI+OLLVM防篡改
└── core:ui-common (UI组件) ← 主题/动画组件
```

> **修订（2026-09-17）**：本文档最初面向 `security/vmp-encryption` 分支撰写。
> 模块拓扑仅列出当时存在的模块；当前仓库共 **25 个模块**（8 个 `core:*`：`agent, common,
> database, domain, network, security, ui-common, wechat`；15 个 `feature:*`；1 个 `:shell`）。
> `feature:localmodel` 已退役（D4），本地推理改由 `core:agent` 的 Rust Cordis Agent 承担。

### 1.2 安全性相关性排序

| 优先级 | 模块 | 安全原因 |
|--------|------|---------|
| **P0** | **core:security** | 安全防线的执行层，所有防护的载体 |
| **P0** | **core:database** | Room DB存储敏感数据（对话记录、API Key配置） |
| **P0** | **core:network** | AI API通信信道，需防MITM和Key泄露 |
| **P1** | **core:agent** | 设备端推理运行时（`liblianyu_agent.so`）完整性，防替换攻击 |
| **P1** | **:app (Application/Activity)** | 应用入口，初始化检测链 |
| **P1** | **core:common** | ContentFilter等安全基线逻辑 |
| **P2** | **feature:memory** | 记忆数据涉及用户隐私 |
| **P2** | **feature:notification** | 保活服务可能被恶意利用 |
| **P3** | feature:chat/companion/groupchat | UI层，安全风险较低 |
| **P4** | feature:settings/profile/ui-common | 配置/UI，风险最低 |

## 四、B层：多层次密码学体系

### 4.1 密钥全生命周期管理（KMS）

```
┌──────────────────────────────────────────┐
│          密钥管理系统（KMS）               │
├──────────────────────────────────────────┤
│                                          │
│  MK（主密钥）                              │
│  ├── 来源：编译期由CI/CD注入               │
│  ├── 存储：Native层硬编码（OLLVM混淆+切分） │
│  ├── 生命周期：编译期→运行时（仅存活200ms）  │
│  └── 销毁：使用后volatile内存清零+内存屏障   │
│                                          │
│  ├── DK（数据密钥）                        │
│  │   ├── 来源：MK派生（KBKDF）             │
│  │   ├── 存储：NEON寄存器（不入内存）        │
│  │   ├── 生命周期：单次操作（μs级）         │
│  │   └── 销毁：寄存器覆写                   │
│  │                                          │
│  └── SK（会话密钥）                         │
│      ├── 来源：DK加密的Token文件             │
│      ├── 存储：TEE（如可用）                 │
│      ├── 生命周期：一次API会话               │
│      └── 销毁：会话结束 → 内存清零            │
│                                          │
└──────────────────────────────────────────┘
```

### 4.2 密码学算法栈

```
C1 ─ 国际/国密算法
    ├── 国际：AES-256-GCM（通信加密）
    │          RSA-4096/ECC P-384（签名）
    │          X25519（密钥交换）
    ├── 国密：SM2（公钥加密/数字签名）
    │          SM3（哈希）
    │          SM4-128（对称加密）
    └──        SM9（标识密码，可选）

C2 ─ 传输层安全
    ├── TLS 1.3（强制，禁用1.2及以下）
    ├── 证书锁定（Certificate Pinning - SHA256）
    ├── QUIC（备选低延迟信道）
    ├── 双向认证（mTLS）
    └── 请求完整性校验（HMAC-SM3）

C3 ─ 存储层加密
    ├── Room DB：全程加密（AES-256-GCM）
    ├── SharedPreferences：AES-256-GCM
    ├── 模型文件：分块加密+完整性HMAC
    ├── 日志文件：加密存储
    └── 临时文件：自动销毁（shred overwrite）

C4 ─ 应用层密码学
    ├── API请求签名（ECDSA + 时间戳+随机数）
    ├── 数字水印（用户身份嵌入数据）
    ├── 隐私计算（关键字段差分隐私）
    ├── 同态加密（部分计算场景，可选）
    └── 零知识证明（认证场景，可选）
```

```
│  • 间接跳转表（动态混淆）                       │

```

### 5.2 VMP 保护目标

| 函数 | 保护等级 | 原因 |
|------|---------|------|
| 密钥派生函数（KBKDF） | **最高** | 主密钥唯一使用者 |
| 环境检测函数（A1-A5） | **最高** | 被Hook则全部失效 |
| 解密函数（decryptData） | **高** | 直接操作明文数据 |
| 签名验证（verifySignature） | **高** | APK完整性基石 |
| Token获取/刷新 | **高** | 用户认证凭证 |
| AI对话签名生成 | **中** | 请求完整性保护 |

### 5.3 OLLVM 混淆配置

```
-fla (控制流平坦化) → 所有关键函数
-bcf (虚假控制流) → VM Interpreter
-sub (指令替换) → 算术运算全部替换
-split (基本块分裂) → 提高分析难度
-string_encryption (字符串加密) → 所有敏感字符串
-indirect_branch (间接分支) → 隐藏函数调用图
```

## 七、白盒AES实现方案

### 7.1 白盒AES设计

```
┌────────────────────────────────────────────┐
│          白盒AES-256（抗DFA/DFA）           │
├────────────────────────────────────────────┤
│                                            │
│  架构：WB-AES（Chow方案增强版）              │
│                                            │
│  ┌──────────┐    ┌──────────┐              │
│  │ 查找表T1  │    │ 查找表T2  │  ← 随机编码 │
│  │ (8→32位)  │    │ (8→32位)  │              │
│  └──────────┘    └──────────┘              │
│        │               │                   │
│        ▼               ▼                   │
│  ┌──────────┐    ┌──────────┐              │
│  │ 查找表T3  │    │ 查找表T4  │  ← 外部编码 │
│  │ (8→32位)  │    │ (8→32位)  │              │
│  └──────────┘    └──────────┘              │
│                                            │
│  • 密钥完全嵌入查找表（不暴露）              │
│  • 每张表唯一随机干扰编码                    │
│  • 轮密钥展开合并入表（无KeySchedule）       │
│  • 抗DFA：每轮checksum验证                  │
│  • 抗DFA：乱序执行 + 冗余计算                │

│  的场景（如API Key本地解密）。               │
│  真正的安全依赖VMP + 短生命周期机制。         │
│                                            │

```

## 九、零信任设计原则总结

| 原则 | 实现方式 |
|------|---------|
| **永不信任** | 每100ms全量检测链，不信任任何静态检查结果 |
| **最小权限** | 密钥使用后立即销毁，不留存 |
| **默认拒绝** | 检测点缺失视为失败 |
| **完全中介** | 所有IO操作走安全层验证 |
| **短生命周期** | 任何秘密<200ms有效 |
| **失败安全** | 任何检测失败触发降级/自毁 |
| **分层防御** | 7层防护，单层突破不影响整体 |
| **行为分析** | 不只看状态，分析执行行为异常 |
| **不可预测** | 随机延迟、随机检测顺序 |
| **可审计** | 所有安全事件记录上链 |
