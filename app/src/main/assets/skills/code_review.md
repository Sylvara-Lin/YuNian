# 代码审查技能 (Code Review Skill)

## 概述

本技能提供结构化的代码审查方法，帮助 AI 在审查代码时保持一致性和完整性。

## 审查流程

### 1. 准备阶段
- 理解变更背景：阅读 PR 描述、关联 Issue、设计文档
- 确认变更范围：新功能、Bug 修复、重构、依赖更新
- 准备测试环境：本地运行测试、检查 CI 状态

### 2. 静态分析
- **代码风格**：命名规范、格式化、导入顺序
- **架构一致性**：模块边界、依赖方向、接口设计
- **错误处理**：异常捕获、错误传播、用户提示
- **资源管理**：内存泄漏、连接关闭、协程取消
- **并发安全**：竞态条件、死锁、线程安全集合

### 3. 逻辑审查
- **业务逻辑正确性**：边界条件、状态机完整性、数据一致性
- **安全性**：输入验证、SQL 注入、XSS、权限校验
- **性能**：N+1 查询、大对象序列化、不必要的计算
- **可测试性**：依赖注入、纯函数、Mock 友好

### 4. 文档与维护性
- **注释质量**：公共 API 文档、复杂算法解释、TODO 规范
- **变更记录**：CHANGELOG 更新、迁移指南、破坏性变更标注
- **测试覆盖**：单元测试、集成测试、边界情况

## 检查清单

```
[ ] 代码是否通过静态分析工具
[ ] 测试是否全部通过
[ ] 是否有破坏性 API 变更
[ ] 错误处理是否完善
[ ] 日志级别是否恰当
[ ] 敏感信息是否硬编码
[ ] 是否遵循项目架构规范
[ ] 文档是否同步更新
```

## 常见问题模式

| 问题类型 | 典型表现 | 修复建议 |
|---------|---------|---------|
| 空指针风险 | `!!`、未判空调用 | 使用 `?.`、`?:`、契约 |
| 资源泄漏 | 协程未取消、监听器未移除 | `use`、`DisposableEffect`、结构化并发 |
| 竞态条件 | 共享可变状态、非原子操作 | `Mutex`、原子类、不可变数据 |
| 过度设计 | 单实现接口、预留扩展点 | YAGNI、按需重构 |
| 复制粘贴 | 重复逻辑、参数化不足 | 提取公共函数、泛型化 |
